# 技术架构

## 分层结构

| 层级 | 主要职责 | 当前实现 |
|---|---|---|
| 媒体解析层 | 获取编码、音轨、帧率、分辨率和时长 | FFprobe |
| 语音感知层 | 本地语音识别、分段和时间戳对齐 | MLX Whisper |
| 视觉取证层 | 抽取关键帧并建立帧与原视频时间映射 | FFmpeg |
| 语义重构层 | 清理口语与错误片段，提炼目标、步骤和结果 | Agent + 结构化数据模型 |
| 质量约束层 | 校验时间范围、证据完整性、置信度和风险 | Pydantic + 业务规则 |
| 语音生成层 | 生成分段旁白或接收本地 TTS 输出 | macOS `say` / 本地音频文件 |
| 时间线重建层 | 按配音时长重算片段长度、局部速度和步骤顺序 | Python 时间线模型 |
| 视觉增强层 | 字幕、点击提示、聚焦、隐私遮挡和转场 | FFmpeg filters |
| 音视频合成层 | 合成旁白、音乐、字幕和视频 | FFmpeg |
| 成片验证层 | 检查轨道、时长、分辨率及关键画面 | FFprobe + 抽帧检查 |

## 数据流

```text
source.mp4
  ├─ media.json
  ├─ transcript.raw.json
  ├─ frames/*.jpg
  └─ frame-index.json
          ↓
   course-draft.json
          ↓
   render-project.json
          ↓
  voice-cache / voice_files
          ↓
       final.mp4
          ↓
   manifest + 成片抽帧
```

## 结构化课程模型

`course-draft.json` 中的每个步骤至少包含：

- 步骤标题与正式旁白；
- 对应原视频的绝对时间范围；
- 口播、页面或页面变化证据；
- 点击对象和完成结果；
- 置信度与风险状态；
- 建议的视觉处理方式。

这种结构使内容重构过程可回溯、可校验，也便于在不覆盖原素材的前提下反复生成不同版本。

## 本地语音策略

发布包不依赖付费语音接口：

- 快速运行时使用 macOS 系统语音；
- 追求更自然音色时，可由任意本地 TTS 生成分段音频，再通过 `voice_provider=files` 接入；
- 项目不内置模型权重，使用者需要单独确认所选模型和音色的许可证。
